# 운영자 판매자 신청 심사

- 경로(계획): `/admin/seller-applications`
- 요구사항: SELLER-002
- [와이어프레임](../wireframes/AdminSellerApplicationsPage.html)

## 조회·처리 계약

`GET /api/v1/admin/seller-applications`의 `status`, `page`, `size`로 신청 목록을 조회한다. 승인에는 `POST /api/v1/admin/seller-applications/{applicationId}/approve`, 반려에는 필수 사유를 담아 `POST /api/v1/admin/seller-applications/{applicationId}/reject`를 사용한다. 서버 `ADMIN` 권한이 필수다.

서류 열람은 `GET /api/v1/admin/seller-applications/{applicationId}/documents/{documentType}/view`를 쓴다(`SELLER.md` 1.7절, `documentType`은 `BUSINESS_LICENSE`/`ID_CARD`/`BANKBOOK`/`MAIL_ORDER_BUSINESS_REPORT`). 응답은 URL이 아니라 서버가 복호화 + 운영자ID·열람시각 워터마크를 합성한 `image/*` 바이너리 스트림이고, `Cache-Control: no-store`로 내려온다.

## 화면 구성

- PC: 상태 필터와 신청 목록, 선택한 신청의 상세·심사 작업을 배치한다.
- 모바일: 각 신청 카드에 브랜드·연락 이메일·신청일·상태를 보이고 상세와 심사 폼을 아래에 펼친다.
- 목록 API에는 `description`이 없고 별도 상세 API도 없다. 소개를 심사에 표시하려면 조회 계약 보완이 필요하다. 현재 와이어프레임은 목록에서 제공되는 정보만 표시한다.
- 선택한 신청의 상세 영역에 서류 4종(사업자등록증·신분증·통장 사본·통신판매업신고증) 열람 버튼을 둔다. 신청 상태(`PENDING`/`APPROVED`/`REJECTED`)와 무관하게 제공한다 — 승인·반려 이후에도 운영자가 서류를 다시 확인할 수 있어야 한다.
- 다운로드 버튼은 두지 않는다. 열람 버튼을 누르면 그 자리에 워터마크가 찍힌 이미지를 바로 띄운다.

## 행동과 이동

필터·페이지를 URL에 남긴다. `PENDING` 건에만 승인·반려를 제공하고 반려 사유를 필수 입력으로 받는다. 심사 전 확인 단계를 두고 제출 중에는 중복 클릭을 막는다. 처리 후 해당 행 상태와 목록을 새로 조회한다.

서류 열람 버튼을 누를 때마다 서버에 다시 요청해 이미지를 받는다(브라우저 캐시에 기대지 않는다). 다른 신청을 선택하거나 화면을 벗어나면 열람 중이던 이미지는 더 이상 보여주지 않는다.

## 상태와 예외

빈 목록, 동시 심사로 상태가 바뀐 경우, 권한 부족, 제출 실패를 구분한다. 승인 성공 시 서버에서 `SELLER` 권한이 활성화되며 운영자 화면은 이를 직접 조작하지 않는다.

서류 열람 실패는 목록·심사 실패와 분리해서 보여준다: 신청 또는 해당 서류가 없으면(`404 SELLER_APPLICATION_NOT_FOUND`) 그 종류만 "서류를 찾을 수 없어요" 안내로 바꾸고, 다른 서류나 목록·심사 동작에는 영향을 주지 않는다. 화면 캡처 방지는 브라우저에서 기술적으로 막을 수 없는 한계이며, 이 화면은 캡처 차단 대신 워터마크(운영자 ID·열람 시각)와 서버 측 열람 기록으로 유출 경로를 추적하는 방식을 쓴다.

## 인수 조건

대기·승인·반려 필터, 페이지 이동·새로고침, 필수 반려 사유, 중복 심사와 모바일 가로 넘침을 확인한다. 서류 4종 각각 열람되는지, 열람마다 재요청되는지, 서류·신청 없음을 구분하는지도 확인한다.

공통: 로딩·빈 결과·실패·권한 오류를 구분하고 키보드 포커스와 직접 진입·뒤로 가기를 확인한다. [공통 디자인 기준](../DESIGN.md)을 따르며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 실제 구현은 별도 이슈에서 수행한다.

## 디자인 적용 (2026-10-13)

필터·신청 목록·선택 상세의 안쪽 여백을 확보하고 선택한 신청은 경계선과 좌측 표시로 구분한다. 심사 작업 영역의 상단 경계선을 강조한다.

[공통 디자인 기준](../DESIGN.md)을 함께 따른다.
