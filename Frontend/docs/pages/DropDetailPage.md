# 소비자 상품 상세

- 경로: `/drops/:dropId` (`HashRouter`, 실제 URL은 `/#...`)
- 구현 이슈: GR-80 · GR-55 · GR-79 · GR-139
- [와이어프레임](../wireframes/DropDetailPage.html)

## 조회 계약

`GET /api/v1/drops/{dropId}`의 `galleryImages`, `detailImages`, `imageUrls`, `actions`, `serverTime`을 사용한다. 옵션별 재고 재조회는 `GET /api/v1/drops/{dropId}/stocks`를 사용한다. `imageUrls`는 GALLERY URL만 담는 구버전 호환 필드다.

## 화면 구성

- PC: 상단은 갤러리와 상품·구매 정보 2열, 하단은 실제 상품 설명·DETAIL 이미지·배송 안내 순서다. 첫 GALLERY 이미지는 목록 썸네일이다.
- 모바일: 갤러리→상품 정보→행동→설명·DETAIL→배송 순서로 한 열에 배치한다. DETAIL은 원본 비율로 자르지 않고 가로 폭 안에 맞춘다.

GR-138: 갤러리 이미지 위에는 WISH·GRAB 상태 태그를 표시하지 않는다. 상품 정보·구매 영역의 상태 표시와 이미지 전환 동작은 유지한다.

## 행동과 이동

갤러리 썸네일·키보드로 이미지를 바꾸고 서버 `actions`에 따라 WISH 등록/취소, 옵션·수량 선택과 주문, 종료 안내를 제공한다. 주문 동선은 [주문·결제 화면](CheckoutPage.md)으로 이어진다. 상품 상세는 주문을 만들지 않고 고른 옵션·수량으로 `/checkout?dropId=&optionId=&quantity=`에 이동하며, 비회원은 로그인 화면으로 보낸다. 구매 전 최신 재고를 확인하되 최종 판단은 주문 API에 맡긴다.

## 상태와 예외

DETAIL이 없으면 텍스트 설명만 보인다. 이미지 실패 시 대체 설명을 제공하고 하단 이미지는 지연 로딩한다. DRAFT·없는 DROP은 404, CANCELED·ENDED는 상세는 보이되 구매 동작은 숨긴다. 요청 실패·인증 만료를 구분한다.

## 인수 조건

GALLERY만 썸네일에 쓰이고 DETAIL은 하단에 용도별 순서대로 나온다. WISH·GRAB·ENDED·CANCELED와 이미지 1장·DETAIL 없음·재고 0·모바일 가로 넘침을 확인한다.

공통: 로딩·빈 결과·실패·권한 오류를 구분하고 키보드 포커스와 직접 진입·뒤로 가기를 확인한다. [공통 디자인 기준](../DESIGN.md)을 따르며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 실제 구현과 API 갱신은 위 구현 이슈에서 수행한다.

## 디자인 적용 (2026-10-13)

PC는 정사각형 갤러리와 구매 정보 2열이다. 제목·가격·상태의 위계를 정리하고 설명 영역은 상단 구분선으로 나눈다. 모바일 갤러리 비율과 DETAIL 원본 비율은 유지한다.

[공통 디자인 기준](../DESIGN.md)을 함께 따른다.

## 실시간 변경 전달 (GR-109·GR-111)

전달 계약과 수치의 정본은 [공개 DROP 실시간 변경 전달 계약](../../../Backend/docs/development/REALTIME_STOCK.md)이다. GR-111의 상세 구독·재조회 제어기를 사용하며 GR-139의 카운트다운도 같은 판매 경계 재조회와 연결된다.

GR-111의 `GET /api/v1/drops/stock-stream?dropIds={dropId}`를 연결한다. `ready` 후 상세·재고를 다시 조회한다. `drop-changed`의 `STOCK`·`STATUS`는 상세 actions와 재고를 함께 갱신하고, `SALES`만 있으면 재고를 조회한다. 브라우저 전체 새로고침 대신 TanStack Query의 정확한 상세·재고 키를 갱신한다.

판매 시작·종료 시각 도달, 화면 복귀·네트워크 복구에도 서버를 다시 조회한다. 서버 actions를 구매 가능 여부의 기준으로 삼고 클라이언트 시각만으로 버튼을 허용하지 않는다. 옵션·입력 수량은 유지하되 부족·비활성·삭제 등 유효하지 않은 선택의 주문은 제한한다.

연속 변경은 조회 키별 최소 2초 간격으로 묶고 같은 키 요청을 병렬로 쌓지 않는다. 조회 중 추가 변경은 후속 조회로 반영하며 이전 화면·연결·요청의 늦은 응답이 덮어쓰지 않게 한다. 정상 연결 중 30~35초, SSE 장애 시 10~12초 주기 조회로 복구한다. 숨김 탭은 연결·주기를 멈추고 복귀 시 재동기화한다. 재접속과 타이머 정리·상세 수렴 목표는 정본 9·12·13절을 따른다.

SSE 실패만으로 상세 전체를 오류 화면으로 바꾸지 않는다. 최초 조회 실패와 갱신 실패를 구분하고, 갱신 실패 시 마지막 성공 데이터를 유지하며 기존 안내·재시도를 사용한다. EventSource의 onerror는 HTTP 상태를 제공하지 않으므로 401·404를 추정하지 않는다. 기존 API 조회의 인증 처리와 404 결과를 따른다. 재고 0·판매 취소·종료에도 최종 주문 판단은 주문 API가 수행한다.

추가 인수 조건: 최초 조회와 구독 사이 변경, 조회 중 변경, 알림 중복·역전, 재연결·조용한 유실, 시작/종료 시각 도달, 재고 0으로 인한 actions 변경, 선택 유지·수량 부족, 숨김/복귀·화면 이동·StrictMode 정리를 검증한다. 수치는 초기 목표이며 실행·성능 검증 결과가 아니다.

## 상세 구매 영역 개편 (GR-139)

### 적용 범위

정보 배치, 현재 재고 표시, WISH 오픈 시각, 종료 안내, 모바일 고정 구매 바와 서버 시각 기준 카운트다운·재고 전환 애니메이션·선택지별 재고 계산을 적용한다.

### 배치와 상태

- 브랜드 → 상품명 → 가격 → 판매 기간·배송 → 상태 영역 → 옵션·수량·합계·구매 버튼 순서다. 제품명 위 상태 줄과 LIMITED DROP 문구를 없앤다. 상품 설명은 하단 상품 상세 설명에만 표시한다.
- 상태 영역은 테두리·타이포 위계로 구분한다. 자간을 넓힌 영문 대문자 라벨, 둥근 배지, 그라데이션, 글로우, 이모지를 추가하지 않는다.
- 구매 가능한 경우 남은 수량과 큰 숫자(고정 숫자 폭)를 표시한다. 10개 이하이면 숫자 색만 위험 색으로 바꾸고 깜빡이거나 흔들지 않는다. 수량 미조회는 ‘확인 중’으로 표시하며 0으로 꾸미지 않는다.
- WISH 가능 상태는 정확한 오픈 날짜·시각과 WISH 수를 보여준다. 상태 영역 아래 기존 옵션 공개 안내와 WISH 등록/취소 버튼을 둔다.
- ENDED·CANCELED·품절은 구매 영역을 기존 사유 문장 하나로 대체한다. 저장 status와 actions가 다르면 구매/WISH 영역은 서버 actions를 따른다.
- PC는 기존 갤러리·정보 2열과 이미지 비율을 유지한다. 720px 이하 구매 가능 화면은 기존 submit 버튼 하나를 하단 고정 바로 옮기고 전체 남은 수량을 함께 표시한다. 옵션·수량·합계는 본문에 남긴다. safe-area와 하단 여백을 확보해 콘텐츠·포커스가 가려지지 않게 한다. 하단 바의 중복 재고 표시는 aria-hidden으로 낭독에서 제외하고 구매 버튼은 유지한다. WISH·종료 화면에는 구매 바가 없다.

### 카운트다운·재고 갱신 규칙

- 오픈 10분 전부터 WISH 상태 영역을 ‘오픈까지’ + `MM:SS`로 바꾼다. 정확한 오픈 시각과 WISH 수는 보조 정보로 유지한다. 0초 이후 서버 응답 대기 중에는 ‘오픈 상태 확인 중’으로 표시한다. 갱신 실패 안내와 재시도 버튼은 상태 영역 바로 위에 둔다. 초 갱신은 남은 밀리초를 기준으로 다음 초 경계에 맞춰 예약한다.
- 상세 serverTime을 수신 시각과 결합해 경과 시간을 계산한다(NFR-008). 쿼리의 dataUpdatedAt과 serverTime으로 오프셋을 계산하며, 캐시 재진입에서도 경과 시간을 유지한다. 기존 useDropStockStream의 판매 시작·종료 재조회 예약과 같은 기준을 사용한다. 타이머만으로 구매 버튼을 허용하지 않으며 0 도달 시 기존 판매 경계 타이머의 재조회 경로를 사용한다. 화면 카운트다운은 별도 요청을 만들지 않는다. 잘못된 시각에는 카운트다운을 숨기고 서버 응답을 기다린다. 화면 이탈·StrictMode·숨김/복귀 시 타이머를 정리·재동기화한다.
- 재고는 기존 SSE 알림→재조회 결과를 사용한다. 스냅샷 간 이전 숫자→최신 숫자 전환을 약 240ms의 짧은 세로 이동으로 표현한다. 첫 조회·같은 값은 움직이지 않고, 증가도 실제 최신 값으로 반영한다. 애니메이션은 조회·구매 판단에 영향을 주지 않는다.
- prefers-reduced-motion에서는 즉시 최신 숫자로 바꾼다. 숫자마다 live region을 두지 않고, 장식용 이전 숫자는 aria-hidden 처리한다.
- 옵션 선택지에 ‘270 · 3개 남음’처럼 재고를 붙인다. 여러 그룹은 현재 다른 그룹 선택과 호환되는 활성 SKU 재고 합계를 표시하고, 정확한 조합 선택 후 기존 selectedStock을 최종 표시한다. 미조회는 ‘재고 확인 중’, 조합 없음은 ‘선택 불가’로 구분한다. 표시 계산만 추가하며 주문 검증은 유지한다.
- 전체 수량·판매 비율·진행 막대는 API에 전체 수량이 없으므로 범위 밖이다.

### 검증

디자인 단계: WISH·구매 가능·품절·종료·취소·actions 전환 지연, PC 1440×900·모바일 390×844, 고정 바·키보드 포커스·가로 넘침·기존 주문 이동을 확인한다. 해당 상세 화면만 시각 기준을 갱신한다.
동작 검증: 10분 경계·0초·서버 시각 차이·정리·재조회 중복 방지, 재고 감소/증가·연속 갱신·reduced motion, 여러 옵션 조합 재고를 단위 테스트와 E2E로 검증한다.

## 관련 DROP 추천 (GR-195)

`GET /api/v1/drops/{dropId}/related`(DROP API 1.4)로 아직 WISH할 수 있는 DROP을 최대 4개 보여 준다. 카드는 목록과 같은 `DropCard`이며 바로 WISH할 수 있다.

- WISH 중인 상세: 배송 안내 아래에 보여 준다. 함께 WISH 기반(`CO_WISH`)이면 "이 DROP을 WISH한 사람들이 좋아할 만한 DROP", 비슷한 DROP(`SIMILAR`)이면 "이런 DROP도 곧 열려요"
- 품절·판매 종료·취소 상세: 구매 영역 바로 아래(상품 상세 설명 위)에 "비슷한 굿즈가 곧 열려요"
- 판매 중인 상세: 구매에 집중하도록 보여 주지 않는다
- 추천이 없거나 조회에 실패하면 영역을 숨긴다. 1분 동안 다시 조회하지 않는다
