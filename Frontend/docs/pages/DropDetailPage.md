# 소비자 상품 상세

- 경로: `/drops/:dropId` (`HashRouter`, 실제 URL은 `/#...`)
- 구현 이슈: GR-80 · GR-55 · GR-79
- [와이어프레임](../wireframes/DropDetailPage.html)

## 조회 계약

`GET /api/v1/drops/{dropId}`의 `galleryImages`, `detailImages`, `imageUrls`, `actions`, `serverTime`을 사용한다. 옵션별 재고 재조회는 `GET /api/v1/drops/{dropId}/stocks`를 사용한다. `imageUrls`는 GALLERY URL만 담는 구버전 호환 필드다.

## 화면 구성

- PC: 상단은 갤러리와 상품·구매 정보 2열, 하단은 실제 상품 설명·DETAIL 이미지·배송 안내 순서다. 첫 GALLERY 이미지는 목록 썸네일이다.
- 모바일: 갤러리→상품 정보→행동→설명·DETAIL→배송 순서로 한 열에 배치한다. DETAIL은 원본 비율로 자르지 않고 가로 폭 안에 맞춘다.

## 행동과 이동

갤러리 썸네일·키보드로 이미지를 바꾸고 서버 `actions`에 따라 WISH 등록/취소, 옵션·수량 선택과 주문, 종료 안내를 제공한다. 주문 동선은 [주문·결제 화면](CheckoutPage.md)으로 이어진다. 상품 상세는 주문을 만들지 않고 고른 옵션·수량으로 `/checkout?dropId=&optionId=&quantity=`에 이동하며, 비회원은 로그인 화면으로 보낸다. 구매 전 최신 재고를 확인하되 최종 판단은 주문 API에 맡긴다.

## 상태와 예외

DETAIL이 없으면 텍스트 설명만 보인다. 이미지 실패 시 대체 설명을 제공하고 하단 이미지는 지연 로딩한다. DRAFT·없는 DROP은 404, CANCELED·ENDED는 상세는 보이되 구매 동작은 숨긴다. 요청 실패·인증 만료를 구분한다.

## 인수 조건

GALLERY만 썸네일에 쓰이고 DETAIL은 하단에 용도별 순서대로 나온다. WISH·GRAB·ENDED·CANCELED와 이미지 1장·DETAIL 없음·재고 0·모바일 가로 넘침을 확인한다.

공통: 로딩·빈 결과·실패·권한 오류를 구분하고 키보드 포커스와 직접 진입·뒤로 가기를 확인한다. [공통 디자인 기준](../DESIGN.md)을 따르며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 실제 구현과 API 갱신은 위 구현 이슈에서 수행한다.

## 디자인 적용 (2026-10-13)

PC는 정사각형 갤러리와 구매 정보 2열이다. 제목·가격·상태의 위계를 정리하고 설명 영역은 상단 구분선으로 나눈다. 모바일 갤러리 비율과 DETAIL 원본 비율은 유지한다.

[공통 디자인 기준](../DESIGN.md)을 함께 따른다.

## 실시간 변경 전달 (GR-109 명세·미구현)

전달 계약과 수치의 정본은 [공개 DROP 실시간 변경 전달 계약](../../../Backend/docs/development/REALTIME_STOCK.md)이다. 아래 동작은 후속 이슈에서 구현하며 현재 화면이 지원한다고 간주하지 않는다. 기존 디자인·레이아웃·와이어프레임은 유지한다.

GR-111에서 `GET /api/v1/drops/stock-stream?dropIds={dropId}`를 연결한다. `ready` 후 상세·재고를 다시 조회한다. `drop-changed`의 `STOCK`·`STATUS`는 상세 actions와 재고를 함께 갱신하고, `SALES`만 있으면 재고를 조회한다. 브라우저 전체 새로고침 대신 TanStack Query의 정확한 상세·재고 키를 갱신한다.

판매 시작·종료 시각 도달, 화면 복귀·네트워크 복구에도 서버를 다시 조회한다. 서버 actions를 구매 가능 여부의 기준으로 삼고 클라이언트 시각만으로 버튼을 허용하지 않는다. 옵션·입력 수량은 유지하되 부족·비활성·삭제 등 유효하지 않은 선택의 주문은 제한한다.

연속 변경은 조회 키별 최소 2초 간격으로 묶고 같은 키 요청을 병렬로 쌓지 않는다. 조회 중 추가 변경은 후속 조회로 반영하며 이전 화면·연결·요청의 늦은 응답이 덮어쓰지 않게 한다. 정상 연결 중 30~35초, SSE 장애 시 10~12초 주기 조회로 복구한다. 숨김 탭은 연결·주기를 멈추고 복귀 시 재동기화한다. 재접속과 타이머 정리·상세 수렴 목표는 정본 9·12·13절을 따른다.

SSE 실패만으로 상세 전체를 오류 화면으로 바꾸지 않는다. 최초 조회 실패와 갱신 실패를 구분하고, 갱신 실패 시 마지막 성공 데이터를 유지하며 기존 안내·재시도를 사용한다. EventSource의 onerror는 HTTP 상태를 제공하지 않으므로 401·404를 추정하지 않는다. 기존 API 조회의 인증 처리와 404 결과를 따른다. 재고 0·판매 취소·종료에도 최종 주문 판단은 주문 API가 수행한다.

추가 인수 조건: 최초 조회와 구독 사이 변경, 조회 중 변경, 알림 중복·역전, 재연결·조용한 유실, 시작/종료 시각 도달, 재고 0으로 인한 actions 변경, 선택 유지·수량 부족, 숨김/복귀·화면 이동·StrictMode 정리를 검증한다. 수치는 초기 목표이며 실행·성능 검증 결과가 아니다.
