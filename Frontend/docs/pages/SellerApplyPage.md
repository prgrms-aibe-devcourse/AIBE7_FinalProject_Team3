# 판매자 등록 신청

- 경로(계획): `/seller/apply`
- 요구사항: SELLER-001, SELLER-003
- [와이어프레임](../wireframes/SellerApplyPage.html)

## 조회·처리 계약

`GET /api/v1/seller-applications/me`로 기존 신청을 확인한다. 신청이 없는 일반 회원만 `POST /api/v1/seller-applications`에 브랜드명, 연락 이메일, 소개를 보낸다. 권한은 `GET /api/v1/users/me`의 역할과 서버 응답을 따른다.

## 화면 구성

- 신청 전에는 소개와 필수 입력 폼, 신청 후에는 브랜드 정보와 `PENDING`·`APPROVED`·`REJECTED` 상태를 표시한다.
- PC는 안내와 폼 2열, 모바일은 안내→폼/상태 한 열이다.

## 행동과 이동

로그인하지 않았으면 로그인으로 이동한 뒤 신청 화면으로 돌아온다. `PENDING`이면 중복 신청 버튼을 숨기고 승인 대기를 안내한다. `APPROVED`면 판매자 작업 공간으로 이동한다. `REJECTED`면 반려 사유를 보여준다. 재신청 허용 여부와 절차는 현재 API 계약에 없으므로 버튼을 제공하지 않는다.

## 상태와 예외

필수 입력 누락, 중복 신청, 권한 오류, 조회·제출 실패를 구분한다. 신청 응답만으로 판매자 권한을 부여하지 않고 서버가 승인한 역할을 다시 확인한다.

## 인수 조건

미신청·대기·승인·반려, 비회원, 중복 제출, 모바일 가로 넘침을 확인한다.

공통: 로딩·실패·권한 오류를 구분하고 키보드 포커스와 직접 진입·뒤로 가기를 확인한다. 기존 색상·글꼴을 유지하며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 실제 구현은 별도 이슈에서 수행한다.
