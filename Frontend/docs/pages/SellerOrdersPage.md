# 판매자 주문·배송

- 경로: `/seller/orders` (`HashRouter`, 실제 URL은 `/#...`)
- 구현 이슈: GR-81
- [와이어프레임](../wireframes/SellerOrdersPage.html)

## 조회 계약

`GET /api/v1/seller/orders`에 `orderStatus`, `paymentStatus`, `dropId`, `page`, `size`를 전달한다. 행을 열면 판매자 주문 상세를 조회하고 배송 준비·송장 등록·송장 수정은 기존 주문·배송 API를 사용한다.

## 화면 구성

- PC: 상태·결제 상태·DROP 필터 위에 주문 목록을 두고 선택 주문의 상세 패널과 송장 입력 패널을 펼친다. 주문번호·상품·상태·금액·배송 작업을 분리한다.
- 모바일: 필터는 줄바꿈하고 주문 행은 핵심 정보와 작업 버튼을 세로로 표시한다. 상세·송장 폼은 행 아래 전체 폭으로 열린다.

## 행동과 이동

필터·페이지를 URL에 보존한다. PAID만 배송 준비, PREPARING만 송장 등록, SHIPPED만 송장 수정이 가능하다. 송장 등록 재시도는 같은 Idempotency-Key를 사용한다.

## 상태와 예외

빈 목록·상세 실패·배송 처리 중·상태 충돌·권한 오류를 구분한다. 결제 취소 확인 중에는 배송 작업을 막는다. `reconciliationRequired`는 이 목록의 일반 결제 상태 필터 링크로 연결하지 않는다.

## 인수 조건

대시보드 PAID 카드와 DROP 상세의 조건이 목록 URL과 결과에 반영된다. 새로고침·뒤로 가기와 배송 상태 전이·실패 후 재조회를 확인한다.

공통: 로딩·빈 결과·실패·권한 오류를 구분하고 키보드 포커스와 직접 진입·뒤로 가기를 확인한다. 기존 색상·글꼴·이미지 비율을 유지하며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 실제 구현과 API 갱신은 위 구현 이슈에서 수행한다.
