# 판매자 DROP 관리

- 경로: `/seller/drops` (`HashRouter`, 실제 URL은 `/#...`)
- 구현 이슈: GR-82 · GR-57
- [와이어프레임](../wireframes/SellerDropsPage.html)

## 조회 계약

`GET /api/v1/seller/drops?status=...&page=...&size=20`으로 본인 DROP만 조회한다. 상태 변경은 기존 공개·취소 API, 상세는 `GET /api/v1/seller/drops/{dropId}`를 사용한다.

## 화면 구성

- PC: 종합에서 분리한 DROP 관리 목록이다. 제목·새 DROP 버튼, 상태 필터, 목록 행에 대표 이미지·상품명·상태·일정·동작을 둔다.
- 모바일: 행은 상품명·상태·주요 동작을 우선 표시하고 부가 정보를 아래로 보낸다. 페이지 가로 넘침 없이 목록을 읽는다.

## 행동과 이동

상태·페이지를 URL에 보존한다. 상품은 판매자 상세로, DRAFT 수정은 `/seller/drops/:dropId/edit`로 이동한다. 공개·출시 취소는 조건에 맞는 DROP에서만 버튼으로 제공한다.

## 상태와 예외

DRAFT는 이미지·일정이 비어 있을 수 있다. 상태별 빈 결과, 로딩·요청 실패·소유권 오류를 구분하고 실패한 상태 변경은 성공처럼 표시하지 않는다.

## 인수 조건

종합의 상태 카드에서 들어온 필터가 적용되고 직접 진입·새로고침·뒤로 가기에도 유지된다. 다른 판매자 DROP은 나타나지 않는다.

공통: 로딩·빈 결과·실패·권한 오류를 구분하고 키보드 포커스와 직접 진입·뒤로 가기를 확인한다. 기존 색상·글꼴·이미지 비율을 유지하며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 실제 구현과 API 갱신은 위 구현 이슈에서 수행한다.
