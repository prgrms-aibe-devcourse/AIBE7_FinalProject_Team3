# 판매자 DROP 등록·편집

- 경로: `/seller/drops/new · /seller/drops/:dropId/edit` (`HashRouter`, 실제 URL은 `/#...`)
- 구현 이슈: GR-80 · GR-56 · GR-79
- [와이어프레임](../wireframes/SellerDropFormPage.html)

## 조회 계약

이미지는 Supabase 서명 업로드 URL을 받은 뒤 DROP 생성·DRAFT 수정 요청의 `images`(GALLERY)와 `detailImages`(DETAIL)에 등록한다. 두 배열의 합계 최대 10장, 파일당 5MB·허용 MIME을 따른다. 누락/null은 수정하지 않고 빈 배열은 해당 용도만 삭제한다.

## 화면 구성

- PC: 기본 정보, GALLERY 이미지, DETAIL 이미지, 옵션 그룹·SKU, 판매·배송, 저장 동작 순서로 배치한다. 용도별 이미지 영역을 분리하고 각각 순서·대체 설명을 표시한다.
- 모바일: 모든 입력 영역을 한 열로 쌓고 이미지 미리보기·대체 설명·위/아래 순서 변경 버튼을 한 묶음으로 둔다. 키보드로 순서를 바꿀 수 있다.

## 행동과 이동

새 DROP은 DRAFT로 저장한다. 편집은 본인 DRAFT만 허용하며 공개 전에는 GALLERY 최소 1장 등 필수값을 검증한다. 이미지 업로드 중 저장을 막고 실패한 파일을 재시도할 수 있게 한다.

## 상태와 예외

DRAFT는 일부 필수값이 비어도 저장 가능하다. DETAIL만 있는 DRAFT는 공개할 수 없다. 이미지 10장 초과, MIME·크기 오류, 업로드 실패, 저장·공개 검증 실패, 권한 오류를 필드 가까이 안내한다.

## 인수 조건

GALLERY/DETAIL 각각 추가·미리보기·순서 변경·삭제·대체 설명이 가능하고 다른 용도는 유지된다. 저장 후 재진입 시 순서·대체 설명이 유지된다.

공통: 로딩·빈 결과·실패·권한 오류를 구분하고 키보드 포커스와 직접 진입·뒤로 가기를 확인한다. 기존 색상·글꼴·이미지 비율을 유지하며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 실제 구현과 API 갱신은 위 구현 이슈에서 수행한다.
