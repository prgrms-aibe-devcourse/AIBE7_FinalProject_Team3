# 판매자 DROP 등록·편집

- 경로: `/seller/drops/new · /seller/drops/:dropId/edit` (`HashRouter`, 실제 URL은 `/#...`)
- 구현 이슈: GR-80 · GR-56 · GR-79 · GR-168(재고 추천)
- [와이어프레임](../wireframes/SellerDropFormPage.html)

## 조회 계약

이미지는 Supabase 서명 업로드 URL을 받은 뒤 DROP 생성·DRAFT 수정 요청의 `images`(GALLERY)와 `detailImages`(DETAIL)에 등록한다. GALLERY 최대 5장, DETAIL 최대 15장, 파일당 5MB·허용 MIME을 따른다. 누락/null은 수정하지 않고 빈 배열은 해당 용도만 삭제한다.

## 화면 구성

- PC: 기본 정보, GALLERY 이미지, DETAIL 이미지, 옵션 그룹·SKU, 판매·배송, 저장 동작 순서로 배치한다. 용도별 이미지 영역을 분리하고 각각 순서·대체 설명을 표시한다.
- 모바일: 모든 입력 영역을 한 열로 쌓고 이미지 미리보기·대체 설명·위/아래 순서 변경 버튼을 한 묶음으로 둔다. 키보드로 순서를 바꿀 수 있다.

## 재고 추천·가격대 참고 (GR-168)

`POST /api/v1/seller/stock-recommendations`(수요 분석 API 5.5)를 호출해 옵션·SKU 영역 아래에 패널로 보여 준다.

- 카테고리와 가격을 정한 활성 SKU가 있으면 입력이 0.5초 멈춘 뒤 조회한다. 입력한 재고가 있으면 함께 보내 배분 비율로 쓴다. 조회 중에는 직전 결과를 유지한다.
- 예상 판매량(범위)과 준비 권장 수량(안전 재고 포함)을 구분해 보여 주고, 근거로 내 실적·시장 평균의 판매량 범위·판매율·품절 비율·표본과 추천에 쓴 기준을 표시한다.
- "추천 수량 채우기"를 눌러야 각 SKU 재고 칸이 추천 배분으로 바뀐다. 판매자는 그 뒤에 고칠 수 있다.
- 가격대 참고: 입력 가격이 같은 카테고리에서 낮은 편·중간·높은 편 중 어디인지, 다른 판매자 DROP의 참고 가격 범위("보통 N원~M원"), 가격대별 판매율. 가격은 추천하지 않는다는 안내를 함께 둔다.
- 표본 부족·잦은 품절·조회 실패는 안내만 하고 입력·저장·공개를 막지 않는다. 카테고리나 가격이 없으면 입력 방법을 안내한다.
- 공개할 때 서버가 그 시점의 추천과 실제 재고를 기록한다(DROP.md 2.5). 화면은 추천 적용 여부를 따로 보내지 않는다.

## 행동과 이동

새 DROP은 DRAFT로 저장한다. 편집은 본인 DRAFT만 허용하며 공개 전에는 GALLERY 최소 1장 등 필수값을 검증한다. 이미지 업로드 중 저장을 막고 실패한 파일을 재시도할 수 있게 한다.

## 상태와 예외

DRAFT는 일부 필수값이 비어도 저장 가능하다. DETAIL만 있는 DRAFT는 공개할 수 없다. 용도별 이미지 개수 초과, MIME·크기 오류, 업로드 실패, 저장·공개 검증 실패, 권한 오류를 필드 가까이 안내한다.

## 인수 조건

GALLERY/DETAIL 각각 추가·미리보기·순서 변경·삭제·대체 설명이 가능하고 다른 용도는 유지된다. 저장 후 재진입 시 순서·대체 설명이 유지된다.

공통: 로딩·빈 결과·실패·권한 오류를 구분하고 키보드 포커스와 직접 진입·뒤로 가기를 확인한다. [공통 디자인 기준](../DESIGN.md)을 따르며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 실제 구현과 API 갱신은 위 구현 이슈에서 수행한다.

## 디자인 적용 (2026-10-13)

흰색 입력 섹션과 라임색 단계 번호를 사용한다. 이미지·옵션·판매 입력의 기존 순서와 모바일 한 열 구성을 유지한다.

[공통 디자인 기준](../DESIGN.md)을 함께 따른다.
