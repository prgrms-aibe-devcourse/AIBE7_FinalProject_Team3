# WISH 상품 목록

- 경로: `/wish` (`HashRouter`, 실제 URL은 `/#...`)
- 구현 이슈: GR-77 · GR-55 · GR-58
- [와이어프레임](../wireframes/WishPage.html)

## 조회 계약

`GET /api/v1/drops?status=WISH&size=24`에 카테고리·상품명·정렬·페이지 조건을 전달한다. 인기 정렬은 `wishCount,desc`이고 기본 날짜 정렬도 유지한다. WISH 등록·취소는 기존 인증 흐름과 WISH API를 사용한다.

## 화면 구성

- PC: 작은 제목·설명 아래 카테고리, 검색, 정렬을 두고 카드 목록을 4열로 표시한다. 큰 소개 배너는 메인으로 옮긴다.
- 모바일: 필터를 여러 줄로 감싸고 카드 2열을 유지한다. 태블릿은 3열이다. 버튼·가격·상품명 두 줄이 겹치지 않는다.

## 행동과 이동

이미지와 상품명은 상세 링크, WISH는 독립 버튼이다. 필터·검색·정렬·페이지를 URL에 보존하고 뒤로 가기 때 복원한다. 로고는 메인, 카드 선택은 상세로 이동한다.

## 상태와 예외

로딩·빈 결과·실패를 목록 자리에서 구분한다. 로그인 필요·등록 불가·전환 배치 지연은 서버 응답으로 안내한다. 이미지 없음은 기본 표시를 사용한다.

## 인수 조건

24개/페이지, PC·태블릿·모바일 4·3·2열, 검색·카테고리·정렬·페이지와 뒤로 가기 복원을 확인한다. 링크와 버튼은 중첩하지 않는다.

공통: 로딩·빈 결과·실패·권한 오류를 구분하고 키보드 포커스와 직접 진입·뒤로 가기를 확인한다. [공통 디자인 기준](../DESIGN.md)을 따르며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 실제 구현과 API 갱신은 위 구현 이슈에서 수행한다.

## 디자인 적용 (2026-10-13)

큰 제목 아래 경계선으로 필터를 구분하고 정사각형 상품 이미지와 작은 모서리의 카드를 사용한다. 등록 버튼, 일정·가격·상태 정보와 4/3/2열 배치는 유지한다.

[공통 디자인 기준](../DESIGN.md)을 함께 따른다.

## 실시간 변경 전달 (GR-109 명세·미구현)

전달 계약과 수치의 정본은 [공개 DROP 실시간 변경 전달 계약](../../../Backend/docs/development/REALTIME_STOCK.md)이다. 아래 동작은 후속 이슈에서 구현하며 현재 화면이 지원한다고 간주하지 않는다. 기존 디자인·레이아웃·와이어프레임은 유지한다.

GR-112에서 현재 페이지의 상품 ID를 `GET /api/v1/drops/stock-stream?dropIds=...` 한 연결로 구독한다. 카드마다 연결하지 않는다. `ready`·`drop-changed` 후 현재 조건의 목록 API를 다시 호출하고, 카드·전체 건수·페이지 수·hasNext를 같은 응답으로 반영한다. 서버 전체 후보 정렬을 유지하며 현재 페이지를 다시 정렬하거나 카드 수량만 바꾸지 않는다.

필터·검색·정렬 변경 시 page=0으로 이동하고, 페이지 이동·뒤로 가기는 URL 조건을 복원한다. ID 집합이 달라지면 이전 연결을 닫고 새 집합으로 교체하되 정본 12절의 접속 간격을 지킨다. 빈 목록에서는 연결하지 않아도 주기 조회를 유지한다. 자동 갱신으로 페이지가 범위를 벗어나도 URL을 강제로 변경하지 않고 기존 빈 결과·범위 밖·이전 이동 처리를 유지한다. totalPages=0이면 페이지 버튼을 숨긴다.

조회 키별 최소 2초 간격으로 알림을 묶는다. 정상 연결 중 30~35초 주기 조회로 화면 밖 상품의 진입·이탈과 조용한 알림 유실을 복구하며 SSE 장애 시 10~12초로 전환한다. WISH 수 변경만의 실시간 전달은 보장하지 않는다. 숨김 탭은 연결·주기를 멈추고 화면 복귀·온라인 복구에 재동기화한다. 이전 필터·연결·응답의 결과를 배제하고 비활성 목록 캐시를 일괄 갱신하지 않는다.

갱신 중 목록·입력·스크롤을 유지한다. SSE 실패는 목록 전체 실패가 아니며, 갱신 실패 시 마지막 성공 데이터를 유지하고 기존 안내·재시도를 사용한다. 최초 조회 로딩·빈 결과·실패와 구분한다. 연결·타이머·리스너는 화면 이탈과 StrictMode 재마운트 시 정리한다. 최신성 목표·재연결·조회 경합은 정본 9·11~13절을 따른다.

WISH 인기순은 주기 조회 시 최신 활성 WISH 집계를 반영한다. 판매 시작·취소 후 해당 목록의 후보 기준에 맞게 상품이 빠지고, 서버가 다음 후보를 채운다. 실제 행동 가능 여부는 서버 응답으로 판단한다.

추가 인수 조건: 시작·취소 알림, WISH 인기순의 주기 갱신, 화면 밖 후보 진입, 빈 목록 복구, 페이지 감소·뒤로 가기, 구독 교체 중 변경과 늦은 응답을 검증한다. 수치는 초기 목표이며 실행·성능 검증 결과가 아니다.
