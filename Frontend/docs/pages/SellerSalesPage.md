# 판매자 판매 실적

- 경로: `/seller/sales` (`HashRouter`, 실제 URL은 `/#...`)
- 구현 이슈: GR-84
- [와이어프레임](../wireframes/SellerSalesPage.html)

## 조회 계약

`GET /api/v1/seller/dashboard/drops?status=...&dropId=...&page=...`의 `orderCount`, `soldQuantity`, `salesAmount`를 사용한다. 결제 확정(`paid_at`)·미취소(`canceled_at` 없음) 주문만 집계하며 `salesAmount`는 배송비 포함 `total_amount`의 누적 합계다.

## 화면 구성

- PC: 상태 필터 아래 상품별 주문 건수·판매 수량·누적 매출 목록을 둔다. 상품 이름은 DROP 상세 또는 그 상품의 주문 목록으로 이동한다.
- 모바일: 각 상품을 카드/행으로 세로 배치해 세 지표와 기준을 함께 읽을 수 있게 한다. 금액이 길어도 가로 넘침이 없다.

## 행동과 이동

`status`, `dropId`, `page`를 URL에 보존한다. 종합의 판매 완료 진입은 ENDED 필터를, DROP 상세의 실적 링크는 해당 `dropId`를 전달한다. 같은 `dropId` 문맥의 주문 목록으로 이동할 수 있다.

## 상태와 예외

실적 없음·취소 주문 제외·다중 페이지를 처리한다. 현재 페이지의 매출 합계를 전체 누적 매출로 표시하지 않는다. 기간별 매출·추이 그래프는 제공하지 않는다.

## 인수 조건

주문 건수와 판매 수량을 구분하고 배송비 포함 누적 매출 안내를 표시한다. 페이지 이동 후에도 전체 합계처럼 보이는 값이 없다.

공통: 로딩·빈 결과·실패·권한 오류를 구분하고 키보드 포커스와 직접 진입·뒤로 가기를 확인한다. 기존 색상·글꼴·이미지 비율을 유지하며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 실제 구현과 API 갱신은 위 구현 이슈에서 수행한다.
