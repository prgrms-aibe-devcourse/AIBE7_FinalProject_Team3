# 소비자 메인

- 경로: `/` (`HashRouter`, 실제 URL은 `/#...`)
- 구현 이슈: GR-78
- [와이어프레임](../wireframes/HomePage.html)

## 조회 계약

`GET /api/v1/drops?status=GRAB&sort=soldQuantity,desc&page=0&size=8`와 `status=WISH&sort=wishCount,desc&page=0&size=8`를 각각 조회한다. GRAB은 서버 시각상 구매 가능한 상품만, WISH는 판매 시작 전 상품만 인기 후보에 포함한다.

## 화면 구성

- PC: 소개 영역 다음에 인기 GRAB, 인기 WISH 순서로 두 개의 독립 슬라이드를 배치한다. 각 영역은 카드 4장을 한 번에 보여 준다.
- 모바일: 두 영역을 세로로 쌓고 카드 2장을 한 번에 보여 준다. 태블릿은 3장이다. 이미지·색상·글꼴은 공통 디자인 기준을 따른다.

## 행동과 이동

각 슬라이드는 한 장씩 이동하며 양끝에서 멈춘다. 카드 목록 좌우에 이전·다음 화살표를 배치하고 터치 스와이프와 포커스 상태의 좌우 화살표 키 조작을 제공한다. 숫자·도트 위치 UI와 터치·키보드 안내 문구는 표시하지 않는다. 화살표는 접근 가능한 이름과 키보드 포커스를 유지하고 카드 내용과 겹치지 않는다. 카드 상세 링크와 WISH 버튼을 분리한다. 전체 보기는 해당 인기 정렬의 `/grab` 또는 `/wish`로 이동한다. 모든 로고는 `/`로 이동한다.

## 상태와 예외

두 요청의 로딩·실패·재시도를 영역별로 처리한다. 0개면 빈 상태와 전체 보기, 1개면 카드만 보여 주고 이동 조작을 숨긴다. 전환 배치 지연으로 인기 GRAB 응답의 저장 `status`가 WISH여도 영역은 GRAB으로 취급하고 구매 동작은 상세 `actions`를 따른다.

## 인수 조건

각 영역 최대 8개, 독립 이동, PC 4장·태블릿 3장·모바일 2장, 양끝 정지와 키보드·터치 조작을 확인한다. 두 영역 중 하나만 실패해도 다른 영역은 보인다.

공통: 로딩·빈 결과·실패·권한 오류를 구분하고 키보드 포커스와 직접 진입·뒤로 가기를 확인한다. [공통 디자인 기준](../DESIGN.md)을 따르며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 실제 구현과 API 갱신은 위 구현 이슈에서 수행한다.

## 디자인 적용 (2026-10-13)

기존 hero-background.png를 원본 비율의 브랜드 배너로 사용하고, 배너만으로 소개 영역을 구성한다. 소개 제목·문단·강조 장식·배너 위아래 탐색 링크는 두지 않는다. 하단은 GRAB/WISH 독립 슬라이드와 상태별 처리를 유지하며 섹션 제목으로 구분한다. 섹션 위 영문 보조 제목은 두지 않는다.

[공통 디자인 기준](../DESIGN.md)을 함께 따른다.

## 헤더·판매자 진입 (GR-128)

일반 화면과 `/seller/apply`는 WISH·GRAB 기본 헤더를 사용한다. `users/me.roles`에 SELLER가 있을 때만 그 옆에 SELLER 링크(`/seller`)를 표시한다. 일반 회원은 MY → 판매자 신청 → 운영자 승인 순서로 권한을 취득하며 제출 성공·신청 상태만으로 권한을 추정하지 않는다. 판매자 작업 공간 헤더는 DASHBOARD·DROPS·ORDERS·INVENTORY·SALES와 SHOP(`/wish`) 복귀 링크를 사용한다. 인증 로딩·로그아웃·계정 변경 시에도 실제 역할을 따른다.
