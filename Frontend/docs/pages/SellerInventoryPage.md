# 판매자 재고 현황

- 경로: `/seller/inventory` (`HashRouter`, 실제 URL은 `/#...`)
- 구현 이슈: GR-83
- [와이어프레임](../wireframes/SellerInventoryPage.html)

## 조회 계약

상품별 합계는 `GET /api/v1/seller/dashboard/drops?status=...&page=...`에서, 선택 상품의 옵션별 현황은 `GET /api/v1/seller/drops/{dropId}/stocks`에서 조회한다. 목록의 모든 상품 옵션을 일괄 요청하지 않는다.

## 화면 구성

- PC: 상태 필터와 상품별 가용·확보·판매 수량 목록을 먼저 보여 주고 선택한 DROP의 옵션별 수량 상세를 옆 또는 아래에 둔다.
- 모바일: 상품 목록과 선택 상세를 세로로 쌓는다. 옵션 이름·가용·확보·판매를 화면 폭 안에서 읽을 수 있게 한다.

## 행동과 이동

`status`, `page`, `dropId`를 URL에 보존하고 대시보드·DROP 상세에서 해당 상품으로 바로 들어온다. 가용은 즉시 구매 가능 수량이 아니라는 설명을 표시한다.

## 상태와 예외

0재고·비활성 옵션·ENDED/CANCELED 상품을 구분한다. 선택 상품 재고 조회 실패가 상품 목록을 숨기지 않는다. 존재하지 않거나 소유하지 않은 DROP은 선택을 해제하고 안내한다.

## 인수 조건

상품별 합계와 선택 상품의 옵션별 수량이 서버 응답과 일치한다. 현재 페이지 합계를 전체 재고라고 표시하지 않는다. 모바일 가로 넘침이 없다.

공통: 로딩·빈 결과·실패·권한 오류를 구분하고 키보드 포커스와 직접 진입·뒤로 가기를 확인한다. 기존 색상·글꼴·이미지 비율을 유지하며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 실제 구현과 API 갱신은 위 구현 이슈에서 수행한다.
