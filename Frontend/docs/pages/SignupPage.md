# 회원가입·이메일 인증

- 경로: `/signup` (LOCAL), `/signup?type=social` (소셜 닉네임 단계)
- 요구사항: AUTH-001, AUTH-005~009
- [와이어프레임](../wireframes/SignupPage.html)

## 조회·처리 계약

LOCAL은 `POST /api/v1/auth/email-verification`으로 코드 요청, `/confirm`으로 확인한 뒤 `POST /api/v1/auth/signup`에 비밀번호·닉네임만 보낸다. 인증된 이메일은 HttpOnly 가입 쿠키에 묶이며 가입 완료 요청에 다시 넣지 않는다. 소셜 신규 회원은 서버 콜백의 `signup_required` 이후 `POST /api/v1/auth/oauth2/signup`에 닉네임만 보낸다.

## 화면 구성

- LOCAL: 이메일 입력→6자리 코드 확인→닉네임·비밀번호 입력의 단계형 폼이다. 확인한 이메일을 마지막 단계에 읽기 전용으로 표시한다.
- 소셜: 닉네임 입력만 표시한다. 제공자 이름은 표시하지 않는다(콜백이 제공자를 전달하지 않는다). 본명·휴대폰 번호는 받지 않는다.
- PC는 기존 인증 페이지의 소개/폼 2열, 모바일은 한 열이다.

## 행동과 이동

코드 재발송은 60초 이후 가능하며 5분 유효·시도 횟수 제한을 안내한다. 2단계의 "이메일 다시 입력"은 입력한 이메일을 남긴 채 1단계로 돌아간다. 새로고침하면 1단계부터 다시 시작한다(가입 진행 상태를 브라우저 저장소에 두지 않는다). 코드 확인 후 가입 컨텍스트는 15분 안에 한 번만 사용한다. LOCAL 가입 컨텍스트가 무효면 이메일을 남긴 채 1단계로 돌아가 코드를 다시 받는다. 이미 가입된 이메일은 로그인으로 안내한다. 닉네임 중복/형식 오류는 같은 단계에서 다시 입력한다. LOCAL 가입이 끝나면 자동 로그인 없이 로그인 화면으로 이동한다. 소셜 가입이 끝나면 서버가 인증 쿠키를 발급하므로 로그인 상태로 원래 접근하려던 내부 경로(없으면 WISH)로 이동하고, 같은 화면을 다시 제출할 수 없다. 소셜 가입 화면에서 새로고침하면 원래 경로는 사라져 WISH로 간다. 소셜 가입 컨텍스트가 만료·소비됐거나 그사이 같은 이메일로 가입된 회원이 생기면 로그인 화면으로 돌아가 소셜 로그인부터 다시 시작한다.

## 상태와 예외

코드 발송 응답만으로 가입 여부를 드러내지 않는다. 코드 만료·불일치·시도 초과·기존 이메일·재발송 제한을 구분한다. 비밀번호 규칙과 닉네임 검증을 표시하되 서버 검증을 기준으로 한다. 닉네임·비밀번호 오류는 해당 입력란 아래에 표시한다. 비밀 코드·가입 토큰은 URL에 넣지 않는다.

## 인수 조건

LOCAL 정상 가입과 각 인증 실패, 소셜 닉네임 입력·중복·컨텍스트 만료, 모바일 가로 넘침을 확인한다.

공통: 로딩·실패를 구분하고 키보드 포커스를 확인한다. [공통 디자인 기준](../DESIGN.md)을 따르며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 실제 구현은 별도 이슈에서 수행한다.

## 디자인 적용 (2026-10-13)

로그인과 같은 소개/폼 구성을 사용하고 현재 가입 단계를 라임색과 하단 경계선으로 강조한다. 코드 확인·소셜 가입·오류 단계의 동작은 유지한다.

[공통 디자인 기준](../DESIGN.md)을 함께 따른다.
