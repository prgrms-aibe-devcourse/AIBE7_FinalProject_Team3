# 마이페이지·내 정보

- 경로: `/my` (기존 화면 확장)
- 요구사항: AUTH-004, MY-001, MY-003
- [와이어프레임](../wireframes/MyPage.html)

## 조회·처리 계약

`GET /api/v1/users/me`로 본인 이메일·닉네임·역할·프로필 이미지를, `GET /api/v1/users/me/wishes`로 WISH를, `GET /api/v1/orders`로 주문 목록을 조회한다. 닉네임 변경은 `PATCH /api/v1/users/me`를 사용한다. LOCAL 비밀번호 변경과 프로필 이미지 수정/삭제는 `MEMBER_AUTH.md`의 해당 API를 따른다.

## 화면 구성

- 기존 WISH·주문 2영역 위에 계정 요약과 내 정보 편집 진입을 추가한다. 주문 행은 [주문 상세](OrderDetailPage.md)로 이동한다.
- PC는 계정 요약 아래 WISH·주문 2열, 모바일은 계정→주문→WISH 한 열로 배치한다. 정보 편집은 같은 페이지의 패널로 연다.

## 행동과 이동

닉네임 수정 후 서버 응답으로 표시 값을 갱신한다. 이메일은 조회만 가능하다. LOCAL 계정에만 비밀번호 변경을 제공한다. 판매자 미신청 회원에게 [판매자 신청](SellerApplyPage.md), 승인된 판매자에게 판매자 작업 공간 링크를 보여준다. WISH 항목은 상품 상세로, 주문 항목은 주문 상세로 이동한다.

## 상태와 예외

비회원은 로그인으로 이동한다. 빈 WISH·주문은 각각 독립된 빈 상태다. 닉네임 중복·형식 오류와 저장 실패를 입력 옆에 표시하고 기존 값은 유지한다. 타인의 정보·주문을 노출하지 않는다.

## 인수 조건

계정 유형별 편집, 주문·WISH 빈 상태, 판매자 신청/승인별 링크, 저장 오류, 모바일 가로 넘침을 확인한다.

공통: 로딩·빈 결과·실패·권한 오류를 구분하고 키보드 포커스와 직접 진입·뒤로 가기를 확인한다. 기존 디자인을 유지하며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 실제 구현은 별도 이슈에서 수행한다.
