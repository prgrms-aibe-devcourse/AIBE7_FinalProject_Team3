# 마이페이지·내 정보

- 경로: `/my` (기존 화면 확장)
- 요구사항: AUTH-004, MY-001, MY-003
- [와이어프레임](../wireframes/MyPage.html)

## 조회·처리 계약

`GET /api/v1/users/me`로 본인 이메일·닉네임·역할·프로필 이미지를, `GET /api/v1/users/me/wishes`로 WISH를, `GET /api/v1/orders`로 주문 목록을 조회한다.

- 닉네임 수정은 `PATCH /api/v1/users/me`에 `{ nickname }`을 보내고 변경된 내 정보 응답을 받는다.
- LOCAL 비밀번호 변경은 `PATCH /api/v1/users/me/password`에 `{ currentPassword, newPassword }`를 보내고 성공 시 본문 없는 204를 받는다.
- 두 요청은 실제 백엔드 API를 사용한다(GR-131). 인증 쿠키·CSRF·401 재발급은 공통 클라이언트가 처리한다. 입력 규칙과 오류 코드는 [회원·인증 API](../../../Backend/docs/development/api-spec/MEMBER_AUTH.md) 1.2.3·1.10·1.11절을 따른다.
- 프로필 이미지 등록·변경은 세 단계다(GR-132). `POST /api/v1/users/me/profile-image/upload-url`에 `{ fileName, contentType, fileSize }`를 보내 `uploadUrl`·`imageUrl`을 받고, `uploadUrl`로 파일을 Storage에 직접 `PUT`한 뒤, 업로드가 성공했을 때만 `PUT /api/v1/users/me/profile-image`에 `{ imageUrl }`을 보내 `{ userId, profileImageUrl }`을 받는다. 삭제는 `DELETE /api/v1/users/me/profile-image`이며 본문 없는 204를 받는다. 세 요청은 실제 백엔드 API를 사용하며 형식·오류 코드는 [이미지 업로드 API](../../../Backend/docs/development/api-spec/IMAGE_UPLOAD.md) 1.2절, [회원·인증 API](../../../Backend/docs/development/api-spec/MEMBER_AUTH.md) 1.12·1.13절을 따른다.
- Storage 업로드에는 API 인증 쿠키·CSRF 헤더를 보내지 않는다. `uploadUrl`에는 서명 토큰이 있으므로 화면·URL·브라우저 저장소·로그에 남기지 않고, 표시·저장에는 `imageUrl`만 쓴다.
- 계정 카드의 요약 숫자는 위 조회 응답의 전체 개수(주문·WISH 목록의 `totalElements`)만 사용한다. 상태별 주문 개수는 표시하지 않는다(별도 API 없음).

## 화면 구성

마이페이지는 한 페이지에서 계정 카드, 주문·WISH, 계정 설정 섹션 순서로 구성한다(GR-160). 새 라우트나 탭은 두지 않는다.

- **계정 카드**: 프로필 이미지(없으면 닉네임 첫 글자를 라임 원에 표시), 닉네임, 이메일, 역할 배지(일반 회원·승인된 판매자·운영자), 주문·WISH 전체 개수를 둔다. 계정 설정은 페이지 아래쪽 섹션에서 다룬다. 긴 이메일은 줄바꿈한다.
- **주문·WISH**: PC는 주문을 넓게, WISH를 보조 열로 둔다(2 : 1). 모바일은 계정 카드 → 주문 → WISH → 계정 설정 순서의 한 열이다. 주문 행은 [주문 상세](OrderDetailPage.md)로, WISH 행은 상품 상세로 이동한다.
- **판매 종료·취소 WISH의 비슷한 굿즈(GR-195)**: 상태가 판매 종료·판매 취소인 WISH 행에만 "비슷한 굿즈 보기" 버튼(`aria-expanded`)을 둔다. 누르면 행 아래에 펼쳐 `GET /api/v1/drops/{dropId}/related`(DROP API 1.4)를 그때 조회하고, "비슷한 굿즈가 곧 열려요"와 함께 DROP 이름(상세 링크)·오픈 일정을 최대 4개 보여 준다. 추천이 없으면 "지금 WISH할 수 있는 비슷한 굿즈가 없어요.", 실패하면 다시 시도를 안내한다. 한 번에 한 행만 펼친다.
- **주문 행**: 모든 주문 행 왼쪽에 주문 상태 배지를 둔다. 결제 대기(`PAYMENT_PENDING`)만 라임으로 강조하고 나머지 상태는 회색 배지다. 결제 대기 주문은 오른쪽에 "결제하기" 버튼(결제 화면 `/checkout/:orderId`), 그 밖의 상태는 "주문 상세" 버튼(테두리 버튼, [주문 상세](OrderDetailPage.md))을 둔다. 주문번호·상품명·주문일·총액은 유지한다.
- **계정 설정 섹션**: 프로필 이미지, 닉네임, 비밀번호(LOCAL 계정만), 판매자, 로그아웃 행을 둔다.
  - 프로필 이미지·닉네임·비밀번호 행의 "변경"을 누르면 모달로 폼을 연다. PC는 가운데 다이얼로그, 모바일은 하단 시트이며 열림 애니메이션은 [공통 디자인 기준](../DESIGN.md)을 따른다. 페이지 배치는 밀리지 않는다.
  - 모달은 제목·닫기(X) 버튼·폼·취소/저장 버튼으로 구성한다. 바깥 영역·Esc·닫기·취소로 닫히고, 닫으면 포커스를 누른 "변경" 버튼으로 돌려준다. 열려 있는 동안 뒤 페이지는 조작할 수 없다.
  - 닉네임 모달은 새 닉네임 입력과 저장 버튼이다(이메일은 계정 카드에서만 보여 준다). 비밀번호 모달은 현재 비밀번호·새 비밀번호·새 비밀번호 확인 입력과 변경 버튼이다. 각 비밀번호 입력 오른쪽의 보기 버튼으로 입력값을 글자로 확인할 수 있으며(`aria-pressed`, "○○ 보기/숨기기"), 모달을 닫으면 다시 가려진다. KAKAO·GOOGLE 계정에는 비밀번호 행을 두지 않는다.
  - 프로필 이미지 모달은 현재 이미지(없으면 기본 표시), "이미지 선택" 버튼, 삭제 버튼(등록된 이미지가 있을 때만), 허용 형식·크기 안내("JPG, PNG, WebP · 5MB 이하"), 취소/저장 버튼이다. 모달을 열면 "이미지 선택" 버튼에 포커스한다. "이미지 선택"은 JPG·PNG·WebP 파일 선택 창을 연다. 파일을 고르면 사전 검증을 통과한 경우에만 현재 이미지 자리에 미리보기를 보여 주고 저장 버튼을 활성화한다. 미리보기는 대체 텍스트("새 프로필 이미지 미리보기")를 둔다. 프로필 이미지 행은 LOCAL·KAKAO·GOOGLE 모든 계정에 둔다.
  - 판매자 행은 판매자 미신청 회원에게 [판매자 신청](SellerApplyPage.md), 승인된 판매자에게 판매자 작업 공간, 운영자에게 판매자 신청 심사 링크를 둔다.
  - 행 설명 문구: 프로필 이미지 "JPG, PNG, WebP · 5MB 이하", 닉네임은 현재 닉네임, 비밀번호 "현재 비밀번호를 확인한 뒤 변경해요.", 판매자는 미신청 "판매자로 활동하려면 신청 후 운영자 승인이 필요해요." / 승인된 판매자 "승인된 판매자예요." / 운영자 "판매자 신청을 심사할 수 있어요.", 로그아웃 "이 기기에서 로그아웃해요."
- 각 폼은 오류와 처리 중 상태를 각각 관리한다. 처리 중인 폼의 제출 버튼만 비활성화하고 "저장 중…" 또는 "변경 중…"을 표시한다. 프로필 이미지 모달은 저장·삭제 중 "이미지 선택"·삭제·저장 버튼을 함께 비활성화하고, 처리 중인 버튼에 "저장 중…" 또는 "삭제 중…"을 표시한다.

## 행동과 이동

닉네임 수정 성공 시 서버 응답으로 내 정보 캐시(`['auth', 'me']`)를 교체해 계정 카드와 설정 행의 닉네임을 갱신한다. 추가 조회 없이 모달을 닫고 "닉네임을 변경했어요."를 안내한다. 헤더에는 닉네임을 글자로 표시하지 않지만, 프로필 이미지가 없으면 헤더 아바타의 첫 글자가 새 닉네임을 따른다. 이메일은 조회만 가능하다.

프로필 이미지는 파일을 고르기만 해서는 요청하지 않는다. 저장을 누르면 업로드 URL 발급 → Storage 업로드 → 등록 순서로 요청하고, 성공 시 응답의 `profileImageUrl`로 내 정보 캐시의 해당 값만 바꾼다(다시 조회하지 않는다). 계정 카드와 헤더 아바타가 함께 바뀌며, 모달을 닫고 "프로필 이미지를 변경했어요."를 안내한다. 삭제 버튼은 확인 없이 바로 삭제를 요청하고, 성공 시 캐시 값을 `null`로 바꿔 기본 표시로 돌아간 뒤 모달을 닫고 "프로필 이미지를 삭제했어요."를 안내한다. 새 파일을 고른 뒤 저장 전에 삭제를 누르면 현재 등록된 이미지를 지운다.

취소·Esc·바깥·닫기로 모달을 닫으면 고른 파일과 미리보기를 버리고 요청하지 않는다. 다시 열면 현재 이미지부터 시작한다.

저장·삭제 중에도 모달은 닫을 수 있다. 업로드 URL 발급·Storage 업로드 단계에서 닫으면 요청을 중단하고 아무것도 바꾸지 않는다. 등록·삭제 요청을 이미 보낸 뒤 닫으면 그 요청은 서버 결과를 따른다. 성공하면 캐시를 갱신하고 안내를 띄우며, 실패하면 아무것도 표시하지 않는다(기존 이미지 유지).

비밀번호 변경 성공 시 모달을 닫고 "비밀번호를 변경했어요."를 안내한다. 현재와 다른 기기의 로그인 세션은 유지하며 재로그인을 요구하지 않는다. 입력값은 폼 상태에만 두고 모달을 닫으면 사라진다. 실패하면 모달을 연 채 오류를 표시한다.

입력을 고치면 그 입력의 필드 오류와 폼 하단 오류를 지운다. 새 비밀번호를 고치면 새 비밀번호 확인의 불일치 오류도 지운다. 모달 열림 상태는 URL·저장소에 남기지 않는다.

## 상태와 예외

비회원은 로그인으로 이동한다. 빈 WISH·주문은 각각 독립된 빈 상태다. 주문·WISH 조회 중이거나 실패하면 계정 카드의 해당 개수는 숫자 대신 비워 두고 각 영역의 로딩·오류 상태를 따른다. 타인의 정보·주문을 노출하지 않는다.

- 닉네임은 규칙 위반 또는 앞뒤 공백 제거 후 현재 값과 대소문자까지 같으면 요청하지 않는다. 서버의 닉네임 중복·형식·동일 값 오류도 닉네임 필드 오류로 표시한다. 저장 실패 시 계정 카드의 기존 값은 유지한다.
- 현재 비밀번호는 필수값만, 새 비밀번호는 가입과 같은 규칙으로 사전 검증한다. 규칙을 통과한 새 비밀번호가 현재 비밀번호와 같으면 요청하지 않는다. 새 비밀번호 확인이 비었거나 새 비밀번호와 다르면 확인 입력 아래에 안내하고 요청하지 않는다(확인 값은 서버로 보내지 않는다). 서버에서 현재 비밀번호 불일치를 받으면 현재 입력만 비우고 포커스를 옮기며, 그 밖의 실패는 입력을 유지한다.
- 필드 오류는 해당 입력 바로 아래에 표시하고 `aria-invalid`·`aria-describedby`로 연결하며 오류 입력에 포커스를 옮긴다. 모바일 한 열에서도 오류가 다른 입력 아래로 밀리지 않아야 한다.
- 네트워크·서버 오류 등 일반 실패와 비밀번호 변경 불가 오류는 해당 폼 하단의 `role="alert"` 영역에 표시한다. 서버의 `reason`을 그대로 노출하지 않고 오류 코드에 맞춘 문구를 사용한다.
- 프로필 이미지는 파일을 고를 때 사전 검증하고, 위반하면 미리보기를 만들지 않고 요청하지 않는다. 형식이 JPG·PNG·WebP가 아니면 "JPG, PNG, WebP 이미지만 올릴 수 있어요.", 0바이트이거나 5MB(5,242,880바이트)를 넘으면 "5MB 이하의 이미지를 올려주세요.", 파일명이 255자를 넘으면 "파일명은 255자 이하로 지정해주세요."를 안내한다.
- 프로필 이미지 오류는 모달 안 미리보기 아래 한 곳(`role="alert"`)에 표시한다. 업로드 URL 발급의 `VALIDATION_FAILED`는 해당 사전 검증 문구, 발급의 `EXTERNAL_SERVICE_ERROR`와 Storage 업로드 실패는 "이미지를 올리지 못했어요. 잠시 뒤 다시 시도해주세요.", 등록의 `VALIDATION_FAILED`는 "이미지를 등록하지 못했어요. 다시 시도해주세요.", 그 밖의 실패(네트워크·서버·권한, 삭제 실패 포함)는 닉네임·비밀번호와 같은 일반 실패 문구를 쓴다. Storage 업로드가 실패하면 등록을 요청하지 않는다. 실패하면 모달을 연 채 계정 카드·헤더의 기존 이미지를 유지한다.
- 프로필 이미지 주소를 불러오지 못하면 계정 카드·헤더 모두 기본 표시로 바꾼다.

## 인수 조건

계정 카드의 프로필 기본 표시·역할 배지·주문/WISH 개수, 주문 행 상태 배지(결제 대기만 강조)와 결제 대기 주문의 결제 화면 이동·그 밖의 주문 상세 이동, 계정 설정 모달의 열림·닫힘(바깥·Esc·취소, 포커스 복귀, 키보드 포함)과 저장 성공 시 닫힘을 확인한다. 계정 유형별 편집, 닉네임 저장 후 캐시·표시 갱신과 새로고침 유지, 비밀번호 변경 후 모달 닫힘·세션 유지, 새 비밀번호 확인 불일치 시 요청 없음, 사전 검증 시 요청 없음, 저장 중 중복 제출 방지, 필드 오류 위치·연결·포커스와 일반 실패 표시를 확인한다. 주문·WISH 빈 상태, 역할별 판매자 링크, 모바일 가로 넘침도 확인한다.

프로필 이미지는 모든 계정 유형에서 선택 → 미리보기(요청 없음) → 저장 후 계정 카드·헤더 표시와 새로고침 유지, 다른 이미지로 변경, 삭제 후 기본 표시 복귀와 새로고침 유지, 이미지가 없을 때 삭제 버튼 없음, 취소 시 요청 없음, 형식·크기·파일명 위반 시 요청 없음, 발급·Storage·등록·삭제 실패 시 기존 이미지 유지(Storage 실패 시 등록 요청 없음), 처리 중 중복 요청 없음, 키보드만으로 선택·저장·삭제를 확인한다. 헤더 계정 메뉴(열기·닫기·마이페이지 이동·로그아웃 성공과 실패)와 서명 URL이 URL·브라우저 저장소에 남지 않는 것도 확인한다.

공통: 로딩·빈 결과·실패·권한 오류를 구분하고 키보드 포커스와 직접 진입·뒤로 가기를 확인한다. [공통 디자인 기준](../DESIGN.md)을 따르며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 이 문서와 정적 와이어프레임의 갱신 자체가 실제 동작 검증 완료를 의미하지는 않는다.

## 디자인 적용 (2026-10-13)

계정 요약의 상단 경계선과 닉네임을 강조한다. WISH·주문 패널의 안쪽 여백을 통일하고 긴 이메일은 줄바꿈한다.

[공통 디자인 기준](../DESIGN.md)을 함께 따른다.

## 계정 카드·계정 설정 개편 (GR-160)

정보 수정 폼이 계정 영역 안에서 펼쳐져 모바일에서 주문·WISH가 밀리던 구성을, 계정 카드 + 주문·WISH + 계정 설정 섹션으로 바꾼다. 기존 "정보 수정" 토글과 계정 영역 하단 안내(안내 문구·판매자 링크·로그아웃)는 계정 설정 섹션으로 옮긴다. 주요 행동은 검정, 상태 강조는 라임을 쓰고 그림자·장식은 추가하지 않는다.

## 헤더·판매자 진입 (GR-128)

일반 화면과 `/seller/apply`는 WISH·GRAB 기본 헤더를 사용한다. `users/me.roles`에 SELLER가 있을 때만 그 옆에 SELLER 링크(`/seller`)를 표시한다. 일반 회원은 MY → 판매자 신청 → 운영자 승인 순서로 권한을 취득하며 제출 성공·신청 상태만으로 권한을 추정하지 않는다. 판매자 작업 공간 헤더는 DASHBOARD·DROPS·ORDERS·INVENTORY·SALES와 SHOP(`/wish`) 복귀 링크를 사용한다. 인증 로딩·로그아웃·계정 변경 시에도 실제 역할을 따른다.

GR-132부터 로그인 상태 기본 헤더의 MY 링크는 원형 프로필 이미지 버튼(접근 가능한 이름 "계정 메뉴", `aria-expanded`)으로 바꾼다. 이미지가 없거나 불러오지 못하면 계정 카드와 같은 기본 표시(닉네임 첫 글자 + 라임 원)를 쓰고, 이미지는 장식으로 둔다. 버튼을 누르면 바로 아래에 "마이페이지"(`/my`) 링크와 "로그아웃" 버튼이 펼쳐진다. 펼친 메뉴는 페이지 배치를 밀지 않고, Esc(포커스를 버튼으로 돌려줌)·바깥 클릭·메뉴 밖으로 포커스 이동·화면 이동·항목 선택으로 닫힌다. 로그아웃은 계정 설정의 로그아웃과 같이 성공하면 WISH(`/wish`)로 이동하고, 실패하면 로그인 상태를 유지한 채 "로그아웃하지 못했어요. 잠시 뒤 다시 시도해주세요."를 토스트로 안내한다. 처리 중에는 "로그아웃 중…"으로 버튼을 막고, 시도가 끝나면 메뉴를 닫는다. 모바일에서도 버튼·항목은 44px 이상의 터치 영역을 유지하고 헤더 높이는 로그인 전후로 같으며 가로 넘침이 없어야 한다. 비로그인 "로그인" 링크와 판매자 작업 공간 헤더(MY 없음)는 바꾸지 않는다.
