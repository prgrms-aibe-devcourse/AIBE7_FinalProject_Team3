# 판매자 DROP 상세

- 경로: `/seller/drops/:dropId` (`HashRouter`, 실제 URL은 `/#...`)
- 구현 이슈: GR-82 · GR-57 · GR-83
- [와이어프레임](../wireframes/SellerDropDetailPage.html)

## 조회 계약

`GET /api/v1/seller/drops/{dropId}`로 상품·옵션·이미지·일정을, `GET /api/v1/seller/drops/{dropId}/stocks`로 옵션별 재고를 조회한다. 주문·실적의 상세 이동은 필터를 가진 분야별 경로로 보낸다.

## 화면 구성

- PC: 상품명·상태·공개/취소 작업, 일정·설명·이미지와 옵션 운영 정보, 해당 상품의 주문·재고·실적 바로 가기를 배치한다. 종합 대시보드의 긴 목록을 복제하지 않는다.
- 모바일: 상품 상태와 주요 작업을 먼저 표시하고 운영 정보·옵션 현황을 세로로 쌓는다. 표는 읽을 수 있는 행 단위로 바꾸거나 내부 스크롤을 제한적으로 사용한다.

## 행동과 이동

DRAFT만 편집·공개할 수 있고 WISH 취소는 판매 시작 전만 제공한다. 주문·재고·실적은 각각 `dropId`를 URL에 전달한다. 소비자 상세 링크도 제공한다.

## 상태와 예외

소유하지 않은 DROP·없는 ID·잘못된 ID, 공개 검증 실패·상태 전환 충돌·재고 조회 실패를 구분한다. 재고 영역 실패가 상품 기본 정보를 숨기지 않는다.

## 인수 조건

소유권과 상태별 작업을 지키며 해당 DROP의 주문·재고·실적 이동 대상이 정확하다. 재고 수량은 가용·확보·판매를 구분한다.

공통: 로딩·빈 결과·실패·권한 오류를 구분하고 키보드 포커스와 직접 진입·뒤로 가기를 확인한다. 기존 색상·글꼴·이미지 비율을 유지하며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 실제 구현과 API 갱신은 위 구현 이슈에서 수행한다.
