# 로그인

- 경로: `/login` (기존 화면 확장). 소셜 결과 콜백은 `/auth/callback`이 처리하고, 오류는 이 화면에 표시한다
- 요구사항: AUTH-002, AUTH-003, AUTH-006~008
- [와이어프레임](../wireframes/LoginPage.html)

## 조회·처리 계약

LOCAL 로그인은 `POST /api/v1/auth/login`, 소셜 로그인 시작은 `GET /api/v1/auth/oauth2/{provider}` (`kakao`·`google`)를 사용한다. 소셜 콜백은 서버가 처리한 후 프론트엔드로 결과를 전달한다. 인증 상태는 `GET /api/v1/users/me`로 확인한다. 쿠키·CSRF·401 재시도는 별도 인증 연동 범위에서 명세를 따른다.

## 화면 구성

- 인증 동작과 안내 문구는 유지하고 색상·간격은 공통 디자인 기준을 따른다. 이메일·비밀번호 폼 아래에 KAKAO·GOOGLE 버튼, 회원가입 링크를 둔다.
- PC는 소개와 폼 2열, 모바일은 소개→폼 한 열이다. 비밀번호 입력은 가려서 표시한다.

## 행동과 이동

LOCAL 로그인 성공 시 원래 접근하려던 내부 경로로 돌아가고, 없으면 WISH로 이동한다. 소셜 기존 회원은 로그인 완료, 최초 회원은 [회원가입의 닉네임 단계](SignupPage.md)로 이동한다. 계정 연결 필요·인증 실패는 오류 코드에 맞게 안내한다. 반환 경로는 앱 내부 경로만 허용한다.

소셜 버튼은 API 호출이 아니라 서버의 소셜 로그인 시작 주소로 페이지를 이동하며, 이동하는 동안 두 버튼을 다시 누를 수 없다. 제공자를 거쳐 돌아오면 앱이 다시 로드되므로 원래 경로를 `sessionStorage`에 잠시 보관하고 콜백에서 읽은 즉시 지운다. 보관하는 값은 화면 경로뿐이며 토큰·가입 정보는 저장하지 않는다. 콜백은 결과를 처리한 뒤 기록을 남기지 않고(`replace`) 이동하므로 새로고침·뒤로 가기로 다시 처리되지 않는다. 소셜 오류는 이 화면으로 돌아와 폼 하단에 표시하고 다시 시도할 수 있다.

## 상태와 예외

필수값·이메일 형식, 잘못된 자격 증명, 비활성 계정, 소셜 취소/실패, 네트워크 오류와 처리 중을 구분한다. 소셜 오류는 인증 실패(취소와 구분하지 않음)·이메일 제공 필요·계정 연결 필요·비활성 계정·서버 오류·알 수 없는 결과를 구분한다. URL이나 메시지에 토큰·인가 코드를 표시하지 않는다.

## 인수 조건

LOCAL 성공·실패, 소셜 기존/신규/오류, 원래 화면 복귀, 모바일 가로 넘침을 확인한다.

공통: 로딩·실패·권한 오류를 구분하고 키보드 포커스를 확인한다. [공통 디자인 기준](../DESIGN.md)을 따르며 PC 1440×900, 모바일 390×844에서 가로 넘침이 없어야 한다. 실제 구현은 별도 이슈에서 수행한다.

## 디자인 적용 (2026-10-13)

진한 소개 영역에 기존 GRAB 심볼을 사용하고 흰색 폼 영역에 보조 제목·로그인 폼·소셜 동선을 배치한다. 모바일 소개 영역은 축소하고 이미지가 글자를 가리지 않도록 공간을 확보한다.

[공통 디자인 기준](../DESIGN.md)을 함께 따른다.
