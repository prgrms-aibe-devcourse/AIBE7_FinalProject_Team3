# GR-75 페이지 개편 명세

이 문서는 후속 이슈 GR-76~84의 화면 계약이다. 라우터는 `HashRouter`를 유지하며 경로 예시는 해시 뒤 경로다. 기존 색상·글꼴·간격·이미지 비율을 유지하고 PC 1440×900, 태블릿, 모바일 390×844에서 가로 넘침 없이 표시한다. 상세 이미지 배치는 [와이어프레임](wireframes/GR-75-image-wireframe.html)을 따른다.

## 소비자 화면

| 경로             | 내용과 행동                                                                   | 조회 조건                                             |
| ---------------- | ----------------------------------------------------------------------------- | ----------------------------------------------------- |
| `/`              | 인기 GRAB과 인기 WISH를 분리한 메인. 각 영역에 최대 8개와 전체 보기 링크 제공 | 구매 가능한 GRAB은 판매 수량순, WISH는 활성 WISH 수순 |
| `/wish`          | 카테고리·상품명 검색, 작은 카드 목록, 상세 이동·WISH                          | WISH 공개 상품, 24개/페이지                           |
| `/grab`          | 카테고리·상품명 검색, 작은 카드 목록, 상세 이동                               | GRAB 공개 상품, 24개/페이지                           |
| `/drops/:dropId` | 상단 갤러리·상품/구매 정보, 하단 설명·DETAIL 이미지·배송 안내                 | 공개 상세 API와 서버 `actions` 사용                   |

- 로고는 소비자·판매자 영역 모두 `/`로 이동한다. WISH/GRAB 메뉴와 카드의 상세 링크는 유지한다.
- 목록은 PC 4열·태블릿 3열·모바일 2열이다. 기존 카드 이미지 비율을 유지하며 카드 전체는 상세 링크, WISH 동작은 별도 버튼으로 제공한다.
- 메인의 두 슬라이드는 각각 독립적이다. PC는 4장, 태블릿은 3장, 모바일은 2장을 한 번에 보여 주고 한 장씩 이동한다. 양끝에서 멈추며 반복 회전하지 않는다. 현재 위치를 `n / 전체`로 알리고 이전·다음 버튼은 더 이동할 수 없으면 비활성화한다.
- 슬라이드는 터치 스와이프와 포커스가 있는 슬라이드에서의 좌우 화살표 키를 지원한다. 버튼에는 영역 이름을 포함한 접근 가능한 이름을 붙이고 포커스 표시를 유지한다. 카드 선택은 상세로 이동한다. 상품이 0개면 빈 상태와 전체 보기 링크, 1개면 이동 버튼·위치 표시 없이 카드 하나를 보인다.
- GALLERY 이미지는 상단에서 순서대로 탐색하며 첫 이미지가 목록 썸네일이다. DETAIL은 설명 아래에서 순서대로 원본 비율로 표시하고 지연 로딩한다. DETAIL이 없으면 설명 텍스트만 표시한다. 이미지 실패 시 대체 설명을 읽을 수 있어야 한다. 판매자는 용도별 업로드·미리보기·위/아래 순서 변경·삭제·대체 설명을 편집한다. 두 용도 합계 최대 10장, 파일당 5MB와 허용 MIME을 안내한다.

## 판매자 화면

| 경로                    | 역할                                                                | 조회·이동                                                     |
| ----------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------- |
| `/seller`               | 현재 DROP 상태 건수, 주문·결제 건수, 재고 요약, 시작·종료 임박 일정 | 상태 카드→해당 필터 목록, 임박 항목→DROP 상세                 |
| `/seller/drops`         | DROP 관리 목록, 상태 필터·페이지                                    | 상품→`/seller/drops/:dropId`; 새 DROP→`/seller/drops/new`     |
| `/seller/drops/:dropId` | 한 DROP의 운영 정보·작업                                            | 해당 DROP의 주문·재고·실적 화면으로 연결                      |
| `/seller/orders`        | 주문·배송 목록, 상태·DROP 필터, 기존 상세·배송 패널                 | `orderStatus`, `paymentStatus`, `dropId`, `page`를 URL에 보존 |
| `/seller/inventory`     | 상품별 재고, 선택 상품의 옵션별 수량                                | `status`, `page`, `dropId`를 URL에 보존                       |
| `/seller/sales`         | 상품별 결제 확정 주문 수·판매 수량·누적 매출                        | `status`, `page`를 URL에 보존                                 |

- 판매자 메뉴는 종합·DROP 관리·주문배송·재고·판매 실적이다. `/seller`의 긴 DROP 목록과 판매 완료 목록은 분야별 화면으로 이동한다. 기존 주문 상세·배송 패널은 재사용한다.
- 종합의 기본값은 기간 제한 없는 현재 상태 집계다. `dropCounts`, `stockSummary`, 결제 보정 건수는 현재값이다. `orderCounts`·`paymentCounts`에 기간을 지정할 때는 해당 영역에만 `from`·`to`를 적용하고 적용 범위를 표시한다. 주문 건수와 결제 시도 건수를 섞지 않는다.
- `reconciliationRequired`는 일반 결제 상태 필터와 같지 않다. 전용 조회 계약 전에는 숫자와 안내만 표시하고 잘못된 상세 링크를 만들지 않는다.
- 재고의 가용·확보·판매 수량은 분리한다. 가용은 종료 상품과 비활성 옵션을 포함할 수 있어 즉시 구매 가능 수량으로 부르지 않는다. 목록의 현재 페이지 합계를 전체 재고·매출로 표시하지 않는다.
- 매출은 결제 확정(`paid_at` 존재)·미취소(`canceled_at` 없음) 주문의 배송비 포함 `total_amount` 누적 합계다. 기간별 매출·추이 그래프·전체 매출 합계는 이번 범위에 넣지 않는다.

## 공통 인수 조건

- 목록은 로딩·빈 결과·조회 실패를 구분한다. 부분 조회 실패 시 성공한 영역은 유지하고 실패한 영역에서 재시도한다. 인증 만료·권한 오류는 기존 인증 흐름으로 처리한다.
- 필터·페이지·선택 DROP은 URL에 남겨 직접 진입과 뒤로 가기에서 복원한다. 잘못된 ID·쿼리와 없는 리소스는 빈 결과나 오류 상태로 안내한다.
- 모든 이동은 링크, 필터·슬라이드·작업은 버튼으로 제공한다. 키보드 포커스, 터치 조작, 화면 읽기 이름을 유지한다.
- 이 문서는 화면·계약의 목표다. GR-55/56/57은 기존 기본 API 연동을 담당하고 GR-76~84가 인기 정렬·이미지 확장·화면 분리를 담당한다. GR-56의 과거 S3 표기보다 현재 Supabase 이미지 업로드 계약을 따른다.
- 판매자 대시보드·DROP 상세의 디자인 개선 예정 안내는 해당 화면 개편과 시각 비교 기준 확정 후 `AGENTS.md`·`README.md`에서 갱신한다.
